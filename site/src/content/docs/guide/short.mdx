면접이 코앞이라면 깊이보다 **넓이**가 먼저입니다. 모든 주제를 한 번씩 훑어 “들어 본 적 있고, 장단점을 말할 수 있는” 상태를 만들고, 대표 문제 몇 개로 45분 동안 대화를 이끄는 감각을 익힙니다.

<PlanProgress plan="short" />

:::note[원문 학습 가이드의 단기 열]
시스템 설계 주제는 **넓게(breadth)**, 시스템 설계·객체 지향 설계·추가 면접 문제는 **일부(some)** 풀어 봅니다. 엔지니어링 블로그, 실제 아키텍처, 면접 접근법은 기간과 상관없이 모두 포함합니다.
:::

## 시간을 아끼는 요령

- 주제 페이지는 **핵심 요약 → 단점 → 스스로 점검하기** 순서로 먼저 훑고, 막히는 부분만 본문을 자세히 읽으세요.
- 문제 풀이는 개수보다 **흐름**이 중요합니다. 유스케이스와 제약 조건 정리 → 고수준 설계 → 핵심 구성 요소 → 확장의 4단계를 매번 같은 순서로 말해 보세요.
- 지원하는 회사가 정해져 있다면 그 회사의 [엔지니어링 블로그](/resources/engineering-blogs/)를 우선하세요. 면접 문제가 같은 도메인에서 나올 수 있습니다.
- 시간이 남으면 [중기 플랜](/guide/medium/)의 나머지 문제로 넘어가세요. 이미 학습 완료로 표시한 페이지는 그대로 이어집니다.
