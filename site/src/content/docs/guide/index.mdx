> 면접까지 남은 기간(단기, 중기, 장기)에 따라 복습할 주제를 제안합니다.

![면접까지 남은 기간별로 공부할 시스템 설계 주제를 정리한 학습 가이드 그림](@repo/images/OfVllex.png)

## 면접을 위해 여기 있는 걸 전부 알아야 하나요?

**아니요. 면접을 준비하기 위해 여기 있는 내용을 전부 알 필요는 없습니다.**

면접에서 무엇을 묻는지는 다음과 같은 변수에 달려 있습니다.

- 경력이 얼마나 되는지
- 어떤 기술적 배경을 가지고 있는지
- 어떤 포지션에 지원하는지
- 어떤 회사에 지원하는지
- 운

일반적으로 경력이 많은 지원자일수록 시스템 설계를 더 많이 알고 있으리라 기대됩니다. 아키텍트나 팀 리드라면 개별 기여자(individual contributor)보다 더 많이 알고 있으리라 기대될 수 있습니다. 상위 테크 기업은 설계 면접을 한 번 이상 진행할 가능성이 높습니다.

**넓게 시작해서 몇몇 영역은 깊게** 파고드세요. 여러 핵심 시스템 설계 주제를 조금씩 알아 두면 도움이 됩니다. 아래 가이드는 남은 기간, 경력, 지원하는 포지션과 회사에 맞춰 조정하세요.

- **단기** — 시스템 설계 주제를 **넓게** 훑습니다. 면접 문제를 **일부** 풀며 연습합니다.
- **중기** — 시스템 설계 주제를 **넓게, 일부는 깊게** 공부합니다. 면접 문제를 **많이** 풀며 연습합니다.
- **장기** — 시스템 설계 주제를 **넓게, 더 깊게** 공부합니다. 면접 문제를 **대부분** 풀며 연습합니다.

## 나에게 맞는 플랜 고르기

원문 가이드는 기간별로 *무엇을* 다룰지 알려 줍니다. 이 사이트의 학습 플랜은 그 표를 순서가 있는 단계와 체크리스트로 바꾼 것입니다. 기간은 예시이니 자신의 일정에 맞게 늘리거나 줄이세요. 같은 페이지는 여러 플랜에 함께 들어 있으므로, 단기 플랜으로 시작했다가 중기 플랜으로 옮겨도 이미 공부한 기록은 그대로 이어집니다.

## 기간과 상관없이 꼭 할 것

원문 표에서 세 기간 모두에 ✓ 표시가 된 활동입니다. 문제 풀이의 양만 기간에 따라 달라집니다.

1. [시스템 설계 주제](/topics/)를 읽고 시스템이 동작하는 방식을 폭넓게 이해하기
2. 지원하는 회사의 [엔지니어링 블로그](/resources/engineering-blogs/) 글 몇 편 읽기
3. [실제 아키텍처](/resources/real-world-architectures/) 사례 몇 개 읽기
4. [시스템 설계 면접 접근법](/interview/approach/) 복습하기

## 이 사이트로 공부하는 방법

:::tip[학습 흐름]
1. **주제 페이지**는 맨 위의 **핵심 요약**으로 큰 그림을 잡은 뒤 본문을 읽고, 마지막의 **스스로 점검하기**로 이해했는지 확인합니다.
2. **문제 해설**은 바로 읽지 마세요. [면접 접근법](/interview/approach/)의 4단계로 먼저 직접 설계해 본 뒤 비교하면 기억에 훨씬 오래 남습니다.
3. 페이지를 다 읽었으면 맨 아래의 **학습 완료로 표시**를 누르세요. 플랜 체크리스트와 사이드바에 함께 반영됩니다.
4. 틈틈이 [플래시카드](/practice/flashcards/)로 복습합니다. 각 주제 페이지 아래에서 그 주제의 카드만 바로 풀 수도 있습니다.
:::

:::note[진행 기록은 어디에 저장되나요?]
학습 완료 표시와 플래시카드 기록은 이 브라우저의 로컬 저장소(localStorage)에만 저장되며, 어떤 서버로도 전송되지 않습니다. 다른 브라우저나 기기에서는 따로 기록됩니다.
:::
